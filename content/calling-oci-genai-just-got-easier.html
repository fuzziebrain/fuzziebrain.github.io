Calling OCI GenAI Just Got Easier

February 8, 2026 · 4 min read
Adrian Png
Principal Solutions Architect @ Miracle and Owner @ Smartweaver Digital

Perhaps one of the biggest pain point when calling the Oracle Cloud Infrastructure (OCI) Generative AI service (OCI GenAI) is authentication. Like all OCI REST APIs, request signing using an OCI API key is required to call the endpoints. That changed on January 21, 2026, when Oracle announced that developers can now generate "API Keys" that behave like most do with other LLM providers.

Create the API Keys​

  1. In the OCI Console, click on the navigation menu, and navigate to Analytics & AI > Generative AI.
  2. On the Generative AI service page, click on the new link to API Keys.
  3. Click on the button Create API key.
  4. Enter a name and description. Also, select the compartment to place the new API key.
  5. Scroll down, enter the names and expiry dates for both keys that will be generated, and then click the button Create.
  6. IMPORTANT Copy and store both generated keys safely. Then, click the button Close.
  7. If necessary, the keys can be regenerated from the API Key's details page.

IAM Policy​

The use of the API keys require an OCI Identity and Access Management (IAM) policy addition. Create or use an existing IAM policy, and add the following statement:

Allow any-user to use generative-ai-family in compartment <compartment_name> where ALL {request.principal.type='generativeaiapikey'}

Use the Keys​

Next, let's test the newly generated API keys.

NOTE

The commands below assume that you have access to Bash and curl and jq are installed.

  • Read the API key into a Bash environment variable. 
    # Prompt for either of the API keys.
    read -s API_KEY
  • Use curl to call the completions endpoint. The example below generates a simple text response. 
    curl --location 'https://inference.generativeai.us-chicago-1.oci.oraclecloud.com/20231130/actions/v1/chat/completions' \
        --header "Authorization: Bearer ${API_KEY}" \
        --header 'Content-Type: application/json' \
        --silent \
        --data '{ "model": "xai.grok-4", "messages": [{ "role": "user", "content": "Where is the capital of Malaysia?" }]}' \
        | jq -r '.choices[0].message.content'
  • If the model used also supports multimedia inputs, set the IMAGE_URL. 
    IMAGE_URL="https://fuzziebrain.com/assets/images/sunrise-whitehorse-1280x720-c751de502eb414ff30940c710ca94c4e.jpg"
    Or, if you have an image on your file system, encode it using Base64: 
    IMAGE_URL="data:image/jpeg;base64,$(base64 -i samples/bird.jpg)"
  • Then, have the model generate a description of the image provided. 
    curl --location 'https://inference.generativeai.us-chicago-1.oci.oraclecloud.com/20231130/actions/v1/chat/completions' \
        --header "Authorization: Bearer ${API_KEY}" \
        --header 'Content-Type: application/json' \
        --silent \
        --data '{ "model": "xai.grok-4", "messages": [{ "role": "user", "content": [{"type":"text", "text": "What is in this image?"}, {"type":"image_url", "image_url": {"url": "'$IMAGE_URL'"}}]}]}' \
        | jq -r '.choices[0].message.content'

It is important to note that the completions endpoint is different from the URL used when calling OCI GenAI using the OCI REST APIs. There is an additional path /completions at the end of the URL. Also, when working with the endpoint, you should probably use OpenAI's documentation for API usage instructions.

Caveat​

Not all models are compatible the OCI OpenAI chat completions API. Currently, the supported models are:

  • Meta Llama
  • xAI Grok; and
  • OpenAI gpt-oss

As of this blog post, availability is also limited to the following regions:

  • Germany Central (Frankfurt)
  • India South (Hyderabad)
  • Japan Central (Osaka)
  • US East (Ashburn)
  • US Midwest (Chicago)
  • US West (Phoenix)

Closing Thoughts​

I am glad that Oracle is doing a lot to make more and more of its OCI services and offerings compatible with its competitors, thereby helping increase developer adoption!
