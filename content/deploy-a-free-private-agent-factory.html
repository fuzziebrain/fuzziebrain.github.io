Deploy a FREE Private Agent Factory

January 18, 2026 · 15 min read
Adrian Png
Principal Solutions Architect @ Miracle and Owner @ Smartweaver Digital

There were several product announcements and launches at the Oracle AI World 2025 held in Las Vegas last year. One particular product that caught my attention is the Oracle Private Agent Factory (OPAF) that Sandesh Rao spoke about extensively at the conference. The OPAF is designed to cut through the complexity of building enterprise-grade assistants. It’s essentially a no-code/low-code playground that allows both business users and engineers to rapidly design, test, and deploy intelligent "Private Agents" that can securely interact with enterprise data. Rather than getting bogged down in writing custom "glue code" to connect models to databases, the Agent Factory provides a visual environment to "wire" these components together into functional, context-aware workflows.

Here is a closer look at the features and capabilities that, I feel, make OPAF a significant move for enterprise AI:

  • The Template Gallery: To help teams get off the starting blocks even faster, the platform includes a Template Gallery. This is a curated collection of pre-configured agent flows and patterns that you can use as a foundation for your own projects, ensuring you don't have to start with a blank canvas when building common AI use cases. I used this quite a bit to understand how to get started building my own flows.
  • Pre-built Agents: The platform ships with specialized, pre-built agents designed to handle specific data tasks right out of the box:
    • Knowledge Agent: Your go-to for RAG (Retrieval-Augmented Generation) over enterprise documents, using vector search to provide grounded, traceable answers from approved sources like SharePoint or Object Storage.
    • Data Analysis Agent: A powerhouse for structured data that doesn't just run SQL; it performs analysis to understand your tables and views, automatically generating visualizations and natural-language explanations. I briefly played with this one, and it reminded me of the cool Oracle Analytics Cloud feature called Auto Insights.
  • User Management: Security is baked in with robust user management that supports Single Sign-On (SSO) (think OAuth). This allows organizations to manage access centrally through existing corporate identity providers, ensuring that only authorized users can build or interact with private agents while maintaining a seamless login experience.
  • The No-Code Agent Builder: At the heart of the platform is a visual, drag-and-drop interface. It abstracts away the heavy lifting, letting you connect chat inputs, LLMs, and data sources, including native integration with the Oracle Autonomous AI Database using simple visual building blocks.
  • The Private AI Services Container: For those obsessed with data sovereignty, this is a "killer feature." OPAF works with privately hosted instances of LLMs, for example, Ollama and vLLM. This ensures your sensitive data never has to leave your controlled perimeter to visit a third-party AI provider.

Getting Started... Quick​

OPAF is available as a download through Oracle's Software Delivery Cloud. However, you can also find a click-to-launch application from the Oracle Cloud Infrastructure (OCI) Marketplace. Harry Snart covers this approach (and more) in detail on his blog post.

Deploying from the marketplace is a faster way to get started, however, I opted to deploy it "manually" on a compute for a few reasons:

  1. I typically use Network Security Groups (NSGs) to filter network traffic. The installation process after the compute and software are deployed will fail as it will have no egress rule to allow the required network communications.
  2. The OCI Stack creates the instance on a public subnet. I generally do not like to put a compute running web applications on a public subnet.
  3. The default OCI Compute shape selected is VM.Standard2.8. You can size it smaller, but if you changed the architecture to a "flex" shape like VM.Standard.E5.Flex, it doesn't allow you to assign fewer than 8 OCPUs and 64 GB memory, and it also comes with a 500 GB boot volume to start. That's probably an overkill for my first time.

Compute Setup and Installation​

As you work through the interactive installation process later, you will note that it has a option to execute commands on a Compute instantiated with an Oracle Enterprise Linux 8 (OEL8) image, and uses the user opc.

Network Security​

I typically use Network Security Groups when managing port access to OCI resources. For OPAF, ensure that there ingress rules for TCP ports 22 (SSH), and 8080 (OPAF web user inteface). If a quick start configuration is performed later, an instance of the Oracle AI Database 23c Free is deployed. Optionally, allow access to TCP port 1521 if you wish to connect to the database. Finally, ensure that there are egress rules to any OCI resources, e.g., Oracle Autonomous AI Database (ADB), and the Internet. If a proxy is not used, make sure that the compute routes to either an OCI Internet Gateway or NAT Gateway.

Prerequisite Software​

There isn't any that the installer script will take care of.

Oracle Container Registry​

The Oracle Container Registry (OCR) is Oracle public repository of Docker containers for anyone to run their products as a container. It requires an Oracle account to login, and with the migration to SSO, an Auth Token is now required where a three-legged authentication cannot be performed. One example is the OPAF deployment process that we are about to embark on. If you haven't already done so, go to the OCR, and sign in with your Oracle account. Then follow these steps:

  1. Click your username on the top-right of the website to expose the options, and select the option Auth Token.
  2. Click the Generate Secret Key button.
  3. After the auth token has been created, click the Copy Secret Key link.

Download the Files​

Either download the software and then upload to the server's /tmp directory, or use Wget to download directly onto the server.

  1. On the OPAF download page on the Software Delivery Cloud, first select the appropriate platform. For example, Linux x86-64.
  2. Check to accept the license agreement.
  3. Click WGET Options.
  4. Download the wget.sh
  5. Upload the wget.sh to the server's /tmp/ directory. 
    scp wget.sh opc@111.111.111.111:/tmp/
  6. Run the script: 
    cd /tmp/
    bash wget.sh
    You will be prompted to enter your Oracle account's username and password. 
    $ bash wget.sh
    SSO User Name:myemaail@example.com
    Password:
    Wait for the download to complete. If necessary, check the log file to check the progress and completion of the download.

Run the Installer​

  1. Set environment variables: 
    export AF_HOME=/opt/oracle/product/agentfactory
    export INSTALLER_FILE_PATH="/tmp/applied_ai.tar.gz"
  2. Create staging directory: 
    sudo mkdir -p ${AF_HOME}
    sudo chown -R $(id -u):$(id -g) ${AF_HOME}
  3. Change working directory for staging files, and extract the installation files. 
    cd ${AF_HOME}
    tar zxf ${INSTALLER_FILE_PATH}

Configure OPAF​

At the end of the installation process, a link would have been provide to get to OPAF's web frontend. I'm not sure about the choice of the port number 8080 for SSL/TLS access, but pay attention to use the HTTPS protocol when you access the URL via a browser. Also, the certificate is self-signed, so you can confidently ignore the error the first time you access OPAF.

Upon first use, the instance's base configuration must be performed.

  1. Begin by creating the administrator account by providing your email address and desired password, then click the Next button.
  2. Click the Install button to install the OPAF components.
  3. If the installation is successful, the button Next will be enabled. Click it to proceed to the LLM configuration step.
  4. OPAF requires a generative and embedding models to be configured. For generative models, four different LLM providers can be configured: OCI Generative AI (OCI GenAI), OpenAI, or locally using vLLM or Ollama. In the diagram below, I have configured it for OCI GenAI. The model ID, endpoint, compartment OCID, and OCI API key (plus user information) must be supplied.
  5. Configure the embedded with a local model, and click both Test connection buttons to ensure the instance can talk to the LLMs successfully.
  6. Save the generative and embedded model configurations, then click the Finish Installation button to complete the process.

Validate the Installation​

  1. Navigate to the same URL to OPAF, and login using the administrator credentials.
  2. After a successful login, navigate to the Prompt lab.
  3. Click to load one of the saved tests, choose a LLM, and click the Generate button to generate a response from the selected LLM.
