Build Autonomous APEX Applications #JoelKallmanDay

October 15, 2025 · 17 min read
Adrian Png
Principal Solutions Architect @ Miracle and Owner @ Smartweaver Digital

Almost a year ago, I wrote about the OCI Generative AI Agents service that can be used to create a Retrieval Augmented Generation (RAG) application using the service. I'm glad to see that the offering has since expanded, and also available in more regions. You can now easily create AI agents that have access to not just the RAG tool, but SQL, function, and other agents, no coding required! However, we are still limited to using the Llama model that is preselected by the service, and may be a problem with customers who are not able to agree to the terms and conditions of use, due to country-specific laws.

Fortunately, there's a solution. Read on.

What is an AI Agent?​

The term "AI Agent" is everywhere now, usually referring to a system powered by a Large Language Model (LLM) that can autonomously plan, break down a goal, use tools (like a search engine or code interpreter), and execute steps to get things done. This is a massive leap in what we consider "autonomy" in software. But here’s the thing: the core idea of an intelligent, goal-directed agent isn't new; it's the result of decades of foundational research.

The earliest, most traditional form of this concept was the Intelligent Agent, and if you've been following my writings and presentations, this was my favourite subject when I was work on my graduate degree at the Institute of System Science, National University of Singapore. Below is a snippet of a term paper I wrote on the automatic bartering of computing resources using intelligent agents.

In classical AI, this was an abstract entity formally defined by its ability to perceive its environment and act rationally to achieve its design goals. This was the era of Symbolic AI, where intelligence was defined by clear, explicit logic.

A perfect example of this is JADE (Java Agent DEvelopment Framework). JADE is an open-source platform that was instrumental in building Multi-Agent Systems (MAS), where multiple agents collaborate. JADE provided the standardized "plumbing" (like the Agent Communication Language, or ACL) so developers could focus on an agent's logic. An agent built with JADE knew things because a human expert hand-coded those things as formal rules or explicit knowledge graphs.

Today, LLMs have largely superseded the need for traditional symbolic knowledge systems in agent design. We no longer rely on human experts or consortiums to meticulously handwrite logic rules and formal knowledge bases (the old Symbolic AI approach). Instead, the agents' reasoning and internal "rules" are learned implicitly by training massive artificial neural networks on vast amounts of data, creating highly flexible and general-purpose intelligence.

My preparations for Kscope25 led me down a technical rabbit hole. I wasn't satisfied with using pre-built frameworks; I needed to understand the native mechanics of modern AI Agents. My goal was to implement an agent from scratch. I sourced a foundational Python example that walks through the entire process: defining the agent's reasoning chain, enabling it to select and execute tools, and managing the core decision-making loop. That's where I learned that the basic outline of what AI Agents do is this:

  1. Load all the required environment variables like API keys.
  2. Configure a LLM client for use by the agent.
  3. Define the tools. In the example, there were two:
    1. wikipedia(q): Queries the Wikipedia API for a search term and returns the plain text summary snippet.
    2. calculate(operation): Uses Python's eval() to securely calculate a mathematical expression (e.g., "5.972e24 * 2").
  4. Define an "Agent" class that stores the LLM client and maintains a history of the conversation, prepopulated with a system prompt. The system prompt defines the core ReAct Loop structure: Thought → Action → PAUSE → Observation → (Loop), and provides the LLM with the syntax for using the available tools (wikipedia and calculate), and a few examples (few-shot training) of how to respond to a user prompt.
  5. Instantiate the Agent class, providing it with the LLM client to use, and a list of tools that it has access to.
  6. When a user prompt is received, loop until either an "answer" can be determined, or the maximum number of iterations is reached.
  7. In each iteration:
    1. Generate response by sending the next_prompt (either the initial query or a new Observation) to the LLM via agent(next_prompt). The LLM's response is stored in result.
    2. Look for a final answer. If result contains the keyword "Answer", the agent has completed the task and the loop terminates.
    3. If an answer is not found, then look for an "action" request, for example, if result contains "PAUSE" and the format "Action: tool_name: argument". If tool use is required, then:
      1. Determine what tool to use.
      2. Execute the tool and capture its results.
      3. Prepare the next prompt. It should have an "observation" that includes the results from executing the tool.
      4. Continue to the next iteration the new "observation" prompt. This allows the agent to use the information in its next "thought".
    4. Append each response (the LLM's thought, action, or answer) to the conversation history.

NOTE

If a tool is not found or there's an error in the result, then the next prompt is set to an error message, which the LLM then sees and adapts to in the next iteration.

I hope that gently explains what a basic AI agent does to provide you intelligent and contextual response. And if it helps, here's a recent quote that I came across that quite recently.

An LLM agent runs tools in a loop to achieve a goal. ~ Simon Willison

You can read his full blog post here.

I would also add that a good agent also has good prompts and carefully crafted examples (for "learning"), and thus, it's mostly what Simon said but also a little bit of prompt engineering skills is required. A good place to start is by using well-published prompts to get start. One great example is the ReAct prompt by Harrison Chase.

Agentic AI Frameworks​

There are quite a few good agentic AI frameworks that you can use today if you live in the Python world, just so you don't need to code everything from scratch. Great examples include:

  • CrewAI (LangChain based)
  • AutoGen
  • LangGraph (also uses LangChain)
  • LlamaIndex
  • Smolgents

Writing a AI agent using Smolagents could be as simple as this!

import os

from smolagents import CodeAgent, WebSearchTool, LiteLLMModel
from dotenv import load_dotenv

load_dotenv()

GROQ_API_KEY = os.environ["GROQ_API_KEY"]

def main():
    model = LiteLLMModel(
        model_id="groq/gemma2-9b-it",
        api_key=GROQ_API_KEY,
    )
    agent = CodeAgent(tools=[WebSearchTool()], model=model, stream_outputs=True)

    agent.run("How many seconds will it take for a car to travel 500 metres if \
        the driver drives at the speed limit on Hwy 1 in Vancouver?")


if __name__ == "__main__":
    main()

That's great! But what about Oracle? Are there any great agentic AI tools that we can use? Of course there is!

OCI Select AI Agents​

For starters, I mentioned the OCI Generative AI Agents service that allows you to create and define AI agents without any code. As mentioned in the opening paragraph, there have been several additions to the service since my previous post. Beyond knowledge bases, or RAG tooling, developers now have access to function calling, executing SQL queries on private Oracle Databases, and interacting with other agents.

The service allows you to define custom endpoints that may or may not include sessions (think conversational histories), guardrails, and more. Each endpoint is available as a REST API call. I will not going into details on how to work with this endpoint as I had already done so in the previous article.

At the time of writing, this service is currently available in the following regions:

  • US Midwest (Chicago)
  • Germany Central (Frankfurt)
  • UK South(London)
  • Brazil East (Sao Paulo)
  • Japan Central (Osaka)
  • US East (Ashburn)
  • US West (Phoenix)

However, as I eluded to at the start of this blog post, at this time, it is not possible to select a specific LLM. Today, the service uses Meta's Llama 3 model, and there are specific usage agreements that users have to agree to. I'm no legal expert but it does primarily affect folks in the European Union where privacy laws are stricter. If that's not you then this is an easy way to get started.

Select AI Agent​

Select AI Agent is an extension of Select AI that was recently announced through the October release notes for the Oracle Autonomous Database (ADB).

With this new capability, developers can create agentic workflows using only SQL and PL/SQL that support AI-driven automation, data interaction, and maintain human-in-the-loop control. These agents can plan and perform actions using built-in or custom tools to query the database, generate responses using RAG, execute functions, perform web searches, or send notifications using e-email or Slack. All that while maintaining context across multi-turn conversations within the database.

The development process starts with an Agent Team. Each agent team is comprised of one or more agents, that in turn is assigned to one or more tasks. Each task may have access to one or more tools to accomplish its goals.

With this release, you will find additional database objects in the C##CLOUD$SERVICE schema, including the following:

  • Package for creating, dropping, enabling, and disabling Select AI Agent artifacts.
    • DBMS_CLOUD_AI_AGENT
  • Views for...
    • Agent, task, and tool definitions.
      • USER_AI_AGENTS
      • USER_AI_AGENTS_ATTRIBUTES
      • USER_AI_AGENT_TOOL
      • USER_AI_AGENT_TOOL_ATTRIBUTES
      • USER_AI_AGENTS
      • USER_AI_AGENT_TASK_ATTRIBUTES
      • USER_AI_AGENT_TEAMS
      • USER_AI_AGENT_TEAM_ATTRIBUTES
    • History of user interactions, task executions, and tool use that may be helpful for providing traceability.
      • USER_AI_AGENT_TEAM_HISTORY
      • USER_AI_AGENT_TASK_HISTORY
      • USER_AI_AGENT_TOOL_HISTORY

NOTE

Each of the views listed come with their "DBA" counterpart.

Here are some steps that should provide you a quickstart to the agentic AI world in your ADB. Yes, it's already in there.

NOTE

This blog post is published on the same day that I'll be speaking alongside Heli Helskyaho on pretty much the same topic at Oracle AI World 2025 (OAIW25). The code for Select AI Agent is what we will be presenting at our session.

If you're going to be at OAIW25, our session information is as follows:

  1. Create a database credential, if you don't already have one. If you have previously worked with Select AI, then this is probably a simple step. Define the variables as per your environment and tenant.

    begin
      begin
        dbms_cloud.drop_credential(
          credential_name => '&credential_name.'
        );
      exception
        when others then null;
      end;

      dbms_cloud.create_credential(
        credential_name => '&credential_name.'
        , user_ocid => '&user_ocid.'
        , tenancy_ocid => '&tenancy_ocid.'
        , private_key => '&private_key.'
        , fingerprint => '&fingerprint.'
      );
    end;

  2. Create an AI profile for the agent. Here, I am using the OCI Generative AI service, and I will need to define an embedding model, as well as a chat model to be used by the agent. The embedding model I have used is cohere.embed-english-v3.0, and for the chat model, I have experimented with a few, and so far, xai.grok-4-fast-reasoning seems to perform the best, and definitely the fastest.

    begin
      begin
        dbms_cloud_ai.drop_profile(
          profile_name => '&ai_profile_name.'
        );
      exception
        when others then null;
      end;

      dbms_cloud_ai.create_profile(
        profile_name => '&ai_profile_name.',
        attributes => '{
              "provider": "oci",
              "credential_name": "OCI_CRED",
              "model": "&model.",
              "embedding_model": "&embedding_model.",
              "region": "&region.",
              "temperature": 0,
              "max_tokens": 4096
          }'
      );
    end;

  3. Define one or more tools that the agent can use to achieve its goals. Tools can be of types:

    • EMAIL. Sends emails when configured. Uses the dbms_cloud_notification package.
    • SLACK. Uses the dbms_cloud_notification package to send messages to Slack.
    • WEB_SEARCH. Performs a web search using OpenAI’s API. OpenAI credentials are required.
    • RAG. Perform a RAG search using the Select AI Vector index.
    • SQL. Queries the database using Select AI.

    To limit the length of this blog post, I will just provide an example of one tool of type SQL.

    1. If you don't already have one, first create an AI profile for the database objects that Select AI has access to. For example: 
      begin
        begin
          dbms_cloud_ai.drop_profile(
            profile_name => '&ai_profile_name._for_inventory'
          );
        exception
          when others then null;
        end;

        dbms_cloud_ai.create_profile(
          profile_name => '&ai_profile_name._for_inventory',
          attributes => '{
                "provider": "oci",
                "credential_name": "OCI_CRED",
                "object_list": [{"owner": "demo02", "name": "FLEET_PART"}],
                "comments": true,
                "annotations": true
            }'
          , description => 'AI profile for searching the fleet part table'
        );
      end;
    2. Next, define the tool using this AI profile. 
      declare
        c_tool_name constant varchar2(128) := 'inventory_search_tool';
      begin
        begin
          dbms_cloud_ai_agent.drop_tool(
            tool_name => c_tool_name
          );
        exception
          when others then null;
        end;

        dbms_cloud_ai_agent.create_tool(
          tool_name => c_tool_name
          , attributes => json_object(
            'tool_type' value 'SQL'
              , 'tool_params' value json_object(
                'profile_name' value '&ai_profile_name._for_inventory'
              )
          )
          , description => trim(q'[
      This tool is used for searching the fleet part inventory. It should be used to
      lookup fleet parts using either the part number or description.
          ]')
        );
      end;

  4. Define one or more tasks that the agent needs to perform. In my demo, there are two tools. The second is of type RAG that allows the agent to look up PDF copies of different car operating manuals. The RAG tool, again, uses one of Select AI's many features.

    declare
      c_task_name constant varchar2(128) := 'diagnose_car_issue_task';
    begin
      begin
        dbms_cloud_ai_agent.drop_task(c_task_name);
      exception
        when others then null;
      end;

      dbms_cloud_ai_agent.create_task(
        task_name => c_task_name
        , attributes => json_object(
            'instruction' value trim(q'[
    You are a polite, and experienced car mechanic. Follow up on the customer's query:
    {query}

    Keep in mind the following:
    1. If there are insufficient details describing the problem to make a diagnosis.
      then request more information.
    2. With the problem description, search the mechanic's guide (diagnostic_tool)
      for a relevant car owner manual to troubleshoot the problem.
    3. Use the appropriate tool to search the fleet part inventory. Use the part
      number to search for the part first. If not found, try using the description.
      When searching by description, it will be helpful to use the database's
      semantic search capabilities. An example of a query is as follows:
        with desired_part as (
          select vector_embedding(ALL_MINILM_L6_V2 using 'the_search_term' as data)
            as search_vector
        )
        select part_number, description
        from fleet_part p, desired_part d
        order by cosine_distance(p.column_with_vector_embedding, d.search_vector)
        fetch approx first 1 rows only with target accuracy 90
    4. If there are sufficient quantities of the identified fleet part, then suggest
      to the customer to make an appointment to bring the vehicle in for repairs.
            ]')
            , 'tools' value json_array(
                'diagnostic_tool'
                , 'inventory_search_tool'
            )
          )
      );
    end;

  5. Create an agent, assign it the AI profile that defines the LLM that it will send requests to, and provide it a role.

    declare
      c_agent_name constant varchar2(128) := 'mechanic_agent';
    begin
      begin
        dbms_cloud_ai_agent.drop_agent(c_agent_name);
      exception
        when others then null;
      end;

      dbms_cloud_ai_agent.create_agent(
        agent_name => c_agent_name
        , attributes => json_object(
          'profile_name' value '&ai_profile_name.'
          , 'role' value trim(q'[
    You are a friendly and experienced car mechanic that is able to diagnose and
    find solutions to common car problems.
          ]')
          , 'enable_human_tool' value 'True'
        )
      );
    end;

  6. Finally, create an agent team. The team can be made up of one or more agents. Each agent will be assigned .

    declare
      c_agent_team_name constant varchar2(128) := 'mechanic_agent_team';
    begin
      begin
        dbms_cloud_ai_agent.drop_team(c_agent_team_name);
      exception
        when others then null;
      end;

      begin
        dbms_cloud_ai.drop_profile('agent$' || c_agent_team_name);
      exception
        when others then null;
      end;

      dbms_cloud_ai_agent.create_team(
        team_name => c_agent_team_name
        , attributes => json_object(
          'agents' value json_array(
            json_object(
              'name' value 'mechanic_agent'
              , 'task' value 'diagnose_car_issue_task'
            )
          )
          , 'process' value 'sequential'
        )
      );
    end;

Once the agent team is ready, you can "talk" to the Select AI Agent either using:

  • The "select ai {{your_prompt}}" interface; or
  • The dbms_cloud_ai_agent.run_team PL/SQL call.

For the Oracle APEX developers, the second option is what you'd want to use.

To perform these natural language interactions in a tool like SQLcl or the SQL Developer VS code plugin, first, set the agent team:

begin
  dbms_cloud_ai.set_conversation_id(null);
  dbms_cloud_ai_agent.set_team(team_name  => 'mechanic_agent_team');
end;

From there, simply interact with the database using the prefix select ai agent, for example:

select ai agent My car won't start!;

Am I Obsolete?​

The advent and proliferation of LLMs, RAG, and AI agents in the last few years, greatly reminds me of the end of the era for film cameras. As they say, AI won't take away your jobs, but the person who uses AI will. The scary bit about AI agents is it's incredible ability to be "trained" and perform some human task at an extremely fast speed.
