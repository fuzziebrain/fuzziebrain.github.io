Turn Your ADB Into a MCP Server and Use It

January 7, 2026 · 14 min read
Adrian Png
Principal Solutions Architect @ Miracle and Owner @ Smartweaver Digital

It seems that the rage about Model Context Protocol is continuing into the new year with Oracle announcing the release of the MCP server for Oracle Autonomous AI Database (ADB) in December, 2025. MCP's been around, but until now, I have yet to find a purpose beyond using a tool like Claude Desktop or Cline in Microsoft Visual Studio Code (Cline) to "talk" to my database. Hence, I made it a point to understand how we can work with MCP endpoints with code, and so, here's what I've learned in that journey.

Turning On the Taps​

The first thing that you'll need to do is to turn on the MCP server feature for your ADB. Unlike many of the other features like Oracle APEX, Oracle Machine Learning user interface, etc., the way to turn the MCP server feature on is to add a specific, free-form tag to the resource. Read this if you don't already know what resource tags are.

The name of this tag must be: adb$feature, and the value is this JSON:

{ "name": "mcp_server", "enable": true }

The elements should be self-explantory. Once added, the ADB will begin to update itself. If successful, the ADB's status should be in an Available state, and the tag is committed successfully. If not, and receive the error message below, then chances are, the MCP server feature is not yet available in your ADB's OCI region.

Error returned by Unknown operation operation in Unknown service service.(400, ADB-10000, false) The Autonomous AI Database operation failed due to an unknown error. Timestamp: 2025-12-24T17:19:54.775Z Client version: Oracle-JavaSDK/2.77.0 Request Endpoint: Unknown request endpoint Troubleshooting Tips: See https://docs.oracle.com/en-us/iaas/Content/API/References/apierrors.htm#apierrors_400__400_adb-10000 for more information about resolving this error Also see Unknown API reference link for details on this operation's requirements. To get more info on the failing request, you can enable debug level logs as mentioned in `Using SLF4J for Logging section` in https://docs.oracle.com/en-us/iaas/Content/API/SDKDocs/javasdkconfig.htm. If you are unable to resolve this Unknown service issue, please contact Oracle support and provide them this full error message

Follow the full set of instructions here to complete all the needed steps to enable the ADB MCP server. There are also instructions on how to configure MCP servers for Claude Desktop and Cline.

There are several components to an application that supports MCP. First, it requires a MCP server, in this case, that's the ADB. Then, we need a MCP client that connects to the server. The application then acts as the MCP host that uses these MCP clients to achieve its goals. As of today, MCP supports only two transport methods for communications between the clients and servers: Stdio and Streamable HTTP. Stdio, or standard input and output, is a local stream between the client and server. A server that only supports Stdio will need to be running on the same host as the client. The Streamable HTTP, on the other hand, allows communications between client and server using HTTP with Server-Sent Events. As communications are sent over the HTTP protocol, servers can also implement standard authentication protocol like bearer tokens, APIs, and OAuth.

Since the ADB is a managed service, one might naturally expect that it supports the second transport mechanism. This presents a little challenge to use within the database environment. To secure the MCP server, the service supports either OAuth or bearer token authentication. In the example later, I opt to use bearer tokens.

Tools for AI Agents​

The ADB's MCP server feature exposes custom tools that have been created in the database. These tools are created using the Select AI Agents PL/SQL procedure DBMS_CLOUD_AI_AGENT.CREATE_TOOL, and the access In my previous [blog post](/content/build-autonomous-apex-applications-joelkallmanday, I had created some tools including the INVENTORY_SEARCH_TOOL for searching the FLEET_PART table, and that is what I will use to run the example here. For your convenience, here's a summary of the code:

/**
 * Create the AI profile for searching the FLEET_PART table using natural
 * language.
 */
begin
  begin
    dbms_cloud_ai.drop_profile(
      profile_name => '&ai_profile_name._for_inventory'
    );
  exception
    when others then null;
  end;

  dbms_cloud_ai.create_profile(
    profile_name => '&ai_profile_name._for_inventory',
    attributes => '{
          "provider": "oci",
          "credential_name": "OCI_CRED",
          "object_list": [{"owner": "demo02", "name": "FLEET_PART"}],
          "comments": true,
          "annotations": true
      }'
    , description => 'AI profile for searching the fleet part table'
  );
end;

/**
 * Create the tool for AI agent to use to search the FLEET_PART table when it
 * rationalizes that it needs it.
 */
declare
  c_tool_name constant varchar2(128) := 'inventory_search_tool';
begin
  begin
    dbms_cloud_ai_agent.drop_tool(
      tool_name => c_tool_name
    );
  exception
    when others then null;
  end;

  dbms_cloud_ai_agent.create_tool(
    tool_name => c_tool_name
    , attributes => json_object(
      'tool_type' value 'SQL'
        , 'tool_params' value json_object(
          'profile_name' value '&ai_profile_name._for_inventory'
        )
    )
    , description => trim(q'[
This tool is used for searching the fleet part inventory. It should be used to
lookup fleet parts using either the part number or description.
    ]')
  );
end;

Note that the schema used to create the tool must have the necessary database privileges not only to create the tool, but to perform the task, such as accessing the data. For simplicity, I am connecting to the MCP server using the same database user that both created the tool and contains the table to be queried.

Discovering and Using the Tool​

To help understand how I can use remote MCP servers with code, I started with the Python SDK from OpenRouter, and thus the code is based on what they've provided in the tutorial. Then, since I have access to the OCI Generative AI (OciGenAi) service, I swapped out the LLM calls using the OCI OpenAI compatible SDK

These days, I work on Python projects using uv. You'll want that installed locally if you'd like to follow along. Then execute the following commands:

uv init adb-mcp-client
cd adb-mcp-client
uv add mcp python-dotenv requests oci-genai

My final pyproject.toml looks like this:

[project]
name = "adb-mcp-client"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.13"
dependencies = [
    "mcp>=1.25.0",
    "oci-openai>=1.0.0",
    "python-dotenv>=1.2.1",
    "requests>=2.32.5",
]

The code starts with the following import statements:

import asyncio, os, requests, httpx, json, logging

from typing import Optional
from contextlib import AsyncExitStack

from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client
from oci_openai import AsyncOciOpenAI, OciUserPrincipalAuth
from dotenv import load_dotenv

The python-dotenv package is used then used to load and set more sensitive or dynamic variables. Add a file .env with the variables below, setting their values according to your environment.

Load and set the variables from the .env file by calling the function load_dotenv(). The URLs for authenticating and communicating with the MCP servers, DATABASE_AUTH_URL and DATABASE_URL, are constructed using these variables. The user prompt to be sent to the LLM is also set in the variable QUESTION.

load_dotenv()

REGION_ID = os.getenv("REGION_ID")
ADB_OCID = os.getenv("ADB_OCID")
DB_USER = os.getenv("DB_USER")
DB_PASSWORD = os.getenv("DB_PASSWORD")
DATABASE_URL = f"https://dataaccess.adb.{REGION_ID}.oraclecloudapps.com/adb/mcp/v1/databases/{ADB_OCID}"
DATABASE_AUTH_URL = f"https://dataaccess.adb.{REGION_ID}.oraclecloudapps.com/adb/auth/v1/databases/{ADB_OCID}/token"

PROFILE_NAME = os.getenv("PROFILE_NAME")
SERVICE_ENDPOINT = os.getenv("SERVICE_ENDPOINT")
COMPARTMENT_ID = os.getenv("COMPARTMENT_ID")
MODEL_NAME = "openai.gpt-oss-120b"

QUESTION = "My 2010 Toyota Prius aircon is emitting a foul smell. Do you have a replacement filter?"

Next, authenticate to the ADB's MCP server using a database account.

auth_response = requests.post(
    url=DATABASE_AUTH_URL,
    headers={
        "Content-Type": "application/x-www-form-urlencoded",
        "Accept": "application/json"
    },
    data={
        "grant_type": "password",
        "username": DB_USER,
        "password": DB_PASSWORD
    }
)

NOTE: that the official documentation says to send the content-type header with the value application/json, but that didn't work for me, and thus switched to application/x-www-form-urlencoded.

The response will have a HTTP status code 200 if authentication is successful. The code below demonstrates how we would proceed to:

  1. Obtain a bearer token for the database user to be used to communicate with the MCP server.
  2. Create a httpx client with the authorization header set with the bearer token received. Note that interactions with the MCP server might take a while, and the default timeout for the httpx client may be insufficient. Set it to a reasonable value.
  3. Create a MCP client session.
  4. Obtain a list of tools available to the database user through the MCP server.
  5. Initialize a LLM client, in this case, using the OCI OpenAI compatible SDK.
  6. Start building the message stream, beginning with the system prompt, and the user's query specified in the variable QUESTION.
  7. Call the chat completion endpoint, supplying the messages and list of available tools from the MCP server.
  8. Extend the messages chain with the response.
  9. Check the response to see if a tool call is required.
  10. If tool calling is requested, extract the name and arguments, then use the MCP client to make the requested tool call.
  11. If the tool called responds successfully, append the results to the message chain.
  12. Make a second and final call to the LLM to generate the response for the user, and display it.
if auth_response.status_code == 200:
    bearer_token = auth_response.json().get("access_token") #1

    async with httpx.AsyncClient( #2
      headers={ "Authorization": f"Bearer {bearer_token}"},
      timeout=300
    ) as client:
        async with streamable_http_client(
          url=DATABASE_URL,
          http_client=client
        ) as (read, write, _):
            async with ClientSession(read, write) as session: #3
                final_response = None
                await session.initialize()
                tools = await session.list_tools() #4
                available_tools = [convert_tool_format(tool) for tool in tools.tools]

                async with AsyncOciOpenAI( #5
                    service_endpoint=SERVICE_ENDPOINT,
                    auth=OciUserPrincipalAuth(profile_name=PROFILE_NAME),
                    compartment_id=COMPARTMENT_ID
                ) as llm:
                    messages=[ #6
                        {
                            "role": "system",
                            "content": "You are an experienced car mechanic. Use only the tools available to you to answer the question. Do NOT hallucinate."
                        }
                    ]

                    messages.append(
                        {
                            "role": "user",
                            "content": QUESTION
                        }
                    )

                    response = await llm.chat.completions.create( #7
                        model=MODEL_NAME,
                        tools=available_tools,
                        messages=messages
                    )

                    content = response.choices[0].message
                    messages.append(content.model_dump()) #8

                    if content.tool_calls is not None: #9
                        tool_name = content.tool_calls[0].function.name #10
                        tool_args = content.tool_calls[0].function.arguments #10
                        tool_args = json.loads(tool_args) if tool_args else {} #10

                        try:
                            result = await session.call_tool(tool_name, tool_args) #10
                        except Exception as e:
                            logging.error(f"Error calling tool {tool_name}: {e}")
                            result = None

                        messages.append({ #11
                            "role": "tool",
                            "tool_call_id": content.tool_calls[0].id,
                            "name": tool_name,
                            "content": str(result.content[0])
                        })

                        response = await llm.chat.completions.create( #12
                            model=MODEL_NAME,
                            messages=messages
                        )

                        final_response = f"Your question was:\n{QUESTION}\n\nMy response:\n{response.choices[0].message.content}" #12
                    else:
                        final_response = content.content

                    print(final_response) #12

NOTE: The MCP tool definitions do not quite work with the OpenAI interface, so thanks OpenRouter, I had to include a helper function shared in their instructions.

def convert_tool_format(self, tool):
    converted_tool = {
        "type": "function",
        "function": {
            "name": tool.name,
            "description": tool.description,
            "parameters": {
                "type": "object",
                "properties": tool.inputSchema["properties"],
                "required": tool.inputSchema["required"]
            }
        }
    }

    return converted_tool

My response:
The unpleasant odor coming from the air‑conditioning system is most often caused by a **dirty or clogged cabin‑air filter**. When the filter gets saturated with pollen, dust, mold spores or other contaminants it can circulate a musty, “wet‑dog” smell every time the HVAC blows.

### What we have in stock

### Why replace it
* **Eliminates foul odors** – a fresh filter removes trapped mold and debris.
* **Improves cooling/heating efficiency** – airflow is less restricted.
* **Protects the HVAC blower** – prevents debris from reaching the fan motor.

### Quick DIY replacement (about 5‑10 min)

1. **Locate the filter** – Under the passenger‑side footwell, behind the glove‑box.
2. **Remove the glove‑box** – Open it, push the side stops inward, then let the glove‑box drop down.
3. **Take out the old filter** – There’s a rectangular cover (often held by clips or a simple latch). Release it and pull the filter straight out. Note its orientation (arrow indicating airflow direction).
4. **Inspect** – If it’s dark, wet or smells, it’s definitely time for a new one.
5. **Install the new filter** – Insert the replacement with the airflow arrow pointing toward the rear of the vehicle (away from the cabin). Re‑secure the cover.
6. **Re‑assemble** – Snap the glove‑box back into place and close it.
